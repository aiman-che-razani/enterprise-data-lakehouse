This project has no end-user UI; its "design system" is the operator experience: dashboards, alerts and docs. Keep them consistent.

## Grafana (`monitoring/grafana/dashboards/*.json`, provisioned from that folder)

- Datasource is the provisioned Prometheus with **uid `prometheus`** (`configs/grafana/provisioning/datasources/prometheus.yml`). Never use `${DS_PROMETHEUS}` / `__inputs` — file provisioning does not resolve them.
- Dashboards are generated or hand-edited JSON with unique panel `id`s, a stable `uid` (`retailnexus-*`), UTC timezone, 1m refresh, tags `retailnexus`.
- Layout: a row per question — overview (stat tiles), per-domain breakdown (bar gauges), trends (time series). Overview tiles first; they fill the 24-column grid (4 wide when there are six, 6 wide when there are four).
- Pass-rate colour scale is fixed: red < 0.75, orange 0.75–0.90, yellow 0.90–0.98, green ≥ 0.98; unit `percentunit`. Overview tiles fill the 24-column grid. Counts: green 0 → orange ≥ 1 → red at the alert-critical level. These thresholds mirror the Prometheus alert rules — change both together.
- Only query `retailnexus_*` metrics that exist (`api/main.py`, owned by the `api` agent); `tests/unit/test_monitoring_config.py` enforces it. `data_quality.json` and the Kibana ndjson are generated by `scripts/monitoring/build_*.py` — edit the generator.
- Titles are plain nouns ("Silver — pass rate by domain"), units always set, legends use `{{domain}}`.

## Kibana (`monitoring/elk/kibana/*.ndjson`, `make setup-elk`)

Data view `lakehouse-*`; saved searches keyed on the logged `event` names (`dq_alert`, `contract_violation`, `*_failed`). Column order: scope → layer → domain → check → message.

## Alerts

`summary` is one line naming the layer/domain (`DQ pass rate below 75% for silver/orders`); `description` gives the value and the next action; severity `warning|critical` only; runbook anchors live in `docs/troubleshooting/TROUBLESHOOTING.md`.

## Charts made for reports or artifacts

Follow the `dataviz` skill; one palette across light/dark; label axes and units; never encode meaning by colour alone.

## Do not

Add a frontend framework, hard-code hostnames in dashboards, or ship a dashboard without running the monitoring config tests.
